## Bugs / lessons
1. Supabase grants EXECUTE on new functions to `anon` by default, so `revoke ... from public` alone did NOT lock the write functions. v0.6 revokes from anon/authenticated explicitly.
2. Per-IP 2-minute limit would block different people sharing one mobile-carrier IP (CGNAT). Replaced with generous hourly caps; per-device limits unchanged.
3. Direction card shows only the newest sighting per direction, so a second train reported later replaces the first. Owner CHOSE to keep this (prefers the latest sight over risking the same train listed twice). v0.10 adds `MAXT` in app.js (1 = current behaviour; 2-3 lists several trains). Not a bug by decision.
4. Stop alerts lingered 90 min after the first report and were hidden only if 'running again' beat confirmations by 2. Owner's scenario: stopped 15 min, many confirm, then it runs again but few people bother to say so (people mostly report sightings) -> false alert for up to 90 min. Fixed in v0.11: 15 min lifetime from the LAST confirmation, hidden when running-again >= stopped, auto-resolved by a sighting at the same station (+2 min grace), UI shows both counts.
5. Bug: Arabic station names in the DB but not in the UI. Root cause: `/api/data` was cached 1 h in the Cloudflare edge AND in the browser (`cache-control: max-age=3600`), and the service worker serves the previous app.js first (still requesting the old URL). Fix: 5-min TTL (name edits propagate on their own), `?v=10` URL, sw mh21. If it still shows French: check that the staging Worker's SUPABASE_URL is the SAME project where the SQL was run, and that the ع button is selected.
6. Tab icon did not match the header logo (colours inverted, different file). Root cause: `icons/192.png` was generated separately from the inline header SVG. Fix: both come from `icons/logo.svg`. Browsers cache favicons hard: clear site data / re-add the home-screen app to see the new icon.
7. Lenis smooth scroll never started: `lenis.min.js` is a plain (non-module) script whose top-level `function t` clashes with app.js's global `const t` (SyntaxError), so `new Lenis` threw ReferenceError in onload. Smooth scroll silently fell back to native scrolling (only desktop/mouse devices load Lenis, which is why a phone on staging looked fine). Fix (v0.24): load `dist/lenis.mjs` with dynamic `import()` (own module scope, no imports inside, verified in the npm package, tested locally with the real file). Lesson: never load a third-party classic script into a page whose own globals are `const`.
8. Production could not post sightings while staging could (diagnosis pending the toast code). Staging uses Cloudflare's dummy Turnstile key/secret, which ALWAYS pass, so it hides every production-only problem. Candidates: (a) `bot`: production `TURNSTILE_SECRET` missing/wrong for site key `0x4AAAAAAFlm_A4hyYrAQoBw`, or the widget's allowed hostnames lack `mitrohelper.dhia336.workers.dev`; (b) `db`: production DB lacks migrate_v7-v9 (release order: SQL first) or the service key is wrong; (c) `net`: non-JSON response. v0.25 shows the code in the toast.
9. Root cause of bug 8 (confirmed by reproduction, pending owner's run on production): production DB missed migrations (at least v7 `is_blocked`). Lesson: staging got the full `schema.sql` so it had everything; production only gets migrations, and an unrun one only fails at runtime because plpgsql resolves function names late. Release order in README (SQL first) must include EVERY migration since the last production run; use `prod_catchup_v4_to_v10.sql`.
## Decisions
1. Polling every 15s instead of Supabase Realtime: zero dependencies, fast load, enough for this use.
2. No framework/build: vanilla JS, ~10 KB, fastest load.
3. Writes only through RPC functions so RLS can stay closed.
4. Edge cache TTL (20s) equals poll interval: before (8s TTL vs 20s poll) nearly every poll was a cache miss -> Supabase. Now Supabase load is bounded per Cloudflare datacenter, independent of user count. Cache API has no stale-while-revalidate, so none is used.
5. (Only matters if MAXT>1.) Merge only same-station reports within 4 min (headways are longer, so two trains that close at one station is unlikely). Do NOT merge across stations: a train seen at stations 3 then 7 is indistinguishable from two trains, and wrongly merging would hide a real one.
6. Stop lifetime is activity-based (15 min since last 'still stopped'), not a fixed 90 min: an outage stays up only while distinct people keep confirming. Absence of sightings is NOT treated as a stop (quiet hours / few users would look like an outage); sightings only ever clear a stop.
7b. Sighting-clears-stop rule is same-station only: a train ahead of the blockage reported elsewhere proves nothing. Risk: someone reporting the stuck train at that station as a sighting >2 min after the last confirmation clears the alert wrongly (they can re-confirm to revive it as a fresh alert).
8. Line cards are permanently expanded (owner request): station track always visible, so the page is long (7 lines). If scrolling becomes a problem, consider a sticky line-jump bar rather than bringing collapse back.
9. Navigation for always-expanded cards = sticky badge bar under the header (not collapse). Red dot on a badge = live stop alert on that line. No scroll-spy/active highlight (extra compute, not needed).
10. Lenis is desktop/mouse only by design: on touch devices it adds nothing (it does not smooth touch) and would cost a rAF loop + a download. Loaded from jsDelivr, pinned 1.3.11 (no SRI hash: file not available offline when this was written; not in the service-worker cache, so offline = native scroll).
11. Louage tab removed at owner request. Re-adding means a new nav button + view branch + i18n strings (see git history before v0.12).
12. Map tab removed at owner request, and with it the nav bar (one tab left = pointless). `tab` var still exists but is always 'metro'. Re-adding a view means restoring a nav + the render branch (git history before v0.13).
13. Sightings: 2 slots per line+direction chosen by owner, replacing the earlier 1-slot (MAXT) decision 3. 'Last 3 sights on different lines never disappear' was read as: every line keeps its latest sightings so cards never go empty (implemented as the 2 newest per direction, never expiring). Change `rn<=2` in the view and `SLOTS` in app.js together to alter the slot count.
14. Timers stay local on purpose (absolute timestamps, not a counted-up number: phone sleep/background throttling would make a counter drift). Server requests are only to discover new reports/votes; reduced by adaptive polling (20->60s when nothing changes) rather than by never asking.
15. Cost: the view returns <=28 rows (smaller payload than a 90-min unbounded window) and scans <=30 days via the seen_at index; cached 20s at the edge. Polling backoff cuts Worker requests (the 100k/day free limit) in quiet hours.
16. Freshness: a failed refresh (network error or no data in the response) shows a red label + red underline on the sticky bar instead of silently showing old data. Costs nothing: label updates from a local timer.
17. Last report is remembered per device in localStorage (line, station, direction). Sighting flow gets a one-tap shortcut to the direction step; stop flow only highlights (a stop alert in one tap would be too easy to trigger by accident).
18. 'How it works' lives behind a header '?' button (not auto-opened on first visit). Its text hard-codes the current numbers (2 slots, 90 min, 15 min): keep in sync with the SQL views.
19. Owner clarified 'last 3 sights': the card top shows only the newest sighting of each direction; the 3-sighting view is the expanded station list (3 newest of the line, one per station+direction). Supersedes decision 13 (2 slots).
20. Auto-pause chosen over auto-ban: computed on the fly from existing data (no cron, no table), temporary by design (rolling 24 h / 7 d window), device-based only. Not IP-based (carriers share IPs), not stop-alert-based (false positives). Weakness: two accomplices could downvote a victim's sightings to pause them; and a troll nobody downvotes is not caught (Turnstile + rate limits remain the defence).
21. Testing = same code, second Supabase project, Wrangler `[env.staging]`; Turnstile dummy keys picked by hostname in config.js (default = production key).
22. Share button moved from the page bottom (nobody scrolled there) to the hero corner, and also offered on the report 'thanks' screen (highest-intent moment; that screen now stays 3.5 s instead of 1.7 s). Not put in the header: it is already full on 360px phones.
23. Owner clarified (again) 'keep the last 3': it is a FLOOR, not a cap. Nothing is hidden before its 90-min timer ends (busy hours must look busy, and every report is valuable info, e.g. 2 trains at the same station 30 min apart = headway); only the last 3 (distinct station+direction) of a line+direction survive past 90 min so quiet lines are never empty. Supersedes decisions 19 and 13 for the station list. Duplicates (same station+direction within 4 min) still collapse. Cap: owner set 5 fresh rows per line+direction (`rn<=5` in the view; was 30). Consequence: on a very busy line the oldest fresh sightings drop off before their 90 min are up. Raise `rn<=` if the board looks too empty at rush hour.
24. Merge rule (owner): a 2nd report at the SAME station + direction (so same line) within 3 min deletes the 1st and counts +1 for the new one. An earlier draft (v0.18 first version) also merged reports up to 2 stops apart; that was a misreading and was removed. Trade-off kept on purpose: a train reported at two neighbouring stations is two sightings. Same-device repeats are replaced without +1 (no self-confirmation). Side effects: deleted rows lower raw `sightings` counts in stats; the 2-min per-device rate limit sees one row less.
25. Arabic names written by the assistant, NOT checked against the official Transtu Arabic signage. Least sure: Les Jardins (الحدائق), Cité El Khadhra (حي الخضراء), Cité Municipale (الحي البلدي), Intikala (الانطلاقة; the French spelling may be a typo of Intilaka), Le Pole Tech (القطب التكنولوجي), Le Campus (الحرم الجامعي), Mohamed Manachou (محمد مناشو).

TODO: export `select line_id,pos,ar,fr,en from stations order by line_id,pos;` and regenerate `update_stations.sql`/`schema.sql` seeds so a fresh install matches production.
27. Readability redesign requested by owner (arrows too small/thin, data hard to read). Choices: station name is the headline and the time is a coloured pill (freshness is the thing riders scan for); old data is dashed/muted instead of faded; chips drop the word 'ago'; dark text on light line colours (white-on-lime failed contrast). Freshness colours differ in light/dark mode for contrast. Tip for the next UI change: a headless-Chromium harness with mock `/api/data` + `/api/live` responses (see how this was verified) is much faster than deploying.
28. Theme: explicit `data-theme` attribute resolved before paint instead of CSS-only `prefers-color-scheme`, so a toggle can override the system without a flash. System stays the default and is followed live until the user taps the toggle once. No 'back to system' control (header is tight on 360px; gap/h1 shrink under 400px).
29. 45 min restored (owner): freshness bands rescaled to 15/30/45 so the colours span the whole life of a sighting. The 90 in `schema.sql`/`migrate_v2` for incidents is the OLD stop logic, superseded by v5, left alone.
30. Animations are WAAPI/CSS only, no library, created on tap and removed on finish; confetti is ~40 short-lived elements. Not measured on low-end phones. Disabled by `prefers-reduced-motion`.
31. One logo file `icons/logo.svg` for header `<img>` and tab favicon; 192/512 PNGs are renders of it.
32. Line-number text colour is one themed variable `--nt` (black light / white dark) instead of the contrast-based black/white mix (owner request, v0.23).

Decision: own authentication inside the Worker (password + TOTP + signed cookie) instead of Cloudflare Access, because Access cannot protect a single path on a `workers.dev` address and no custom domain exists. Disabled (404) unless the 3 secrets exist, so a forgotten secret never leaves it open. Security model is in README 'Admin page'. Honest limits: stateless cookies cannot be revoked one by one (re-run the setup script to revoke all); lockout is per network (IPv6 grouped by prefix), a rotating attacker is still stopped by the second factor, not by the lock; I tested the logic, nobody independent audited it, so 'completely secure' is not a claim I can prove: pick a long password and keep the authenticator on a device you control.
